# 0025. Installed settings turn all attribution off

## Status

Accepted (2026-10-14), by the operator. Whether it stops the PR footer awaits
a trial; see "Trial, still open" below. Supersedes the setting part of ADR
0022.

## Context

ADR 0022's trial (2026-10-14) ran a cloud routine on a base that installs
`"attribution": {"sessionUrl": false}`. The commit carried no session
trailer, but the PR body still ended with a `---` /
`_Generated by [Claude Code](<session link>)_` footer. `sessionUrl: false`
does not reach it.

The settings reference says `"attribution": false` hides all attribution. It
needs Claude Code 2.1.281 or later; an older version skips the whole settings
file. Nothing says it reaches the footer. The read-back check of ADR 0024
(verify-body) removes the footer after publication and does not depend on
this change.

## Decision

`settings.base.json` sets `"attribution": false`. A bootstrap test reads it
back from the installed settings as `false`.

## Options considered

- **`sessionUrl: false` alone (ADR 0022).** Rejected: the trial disproved it
  for the footer.
- **The object form `{"commit": "", "pr": "", "sessionUrl": false}`.** No
  old-version risk, but nothing says it reaches the footer either. Rejected
  by the operator in favour of `false`.
- **Server-managed settings.** Not taken: an organisation setting outside the
  base and the instance, invisible to their review.

## Consequences

- Every session on a machine running this base stops adding the
  `Co-Authored-By:` trailer and the `🤖 Generated with` line. ADR 0022's rule
  in the routine prompts and commands now gives both lines in full
  (`Co-Authored-By: Claude <noreply@anthropic.com>` and
  `🤖 Generated with [Claude Code](https://claude.com/claude-code)`), since it
  can no longer rely on the default to supply them; the drift test pins every
  copy. The trailer names no model: the routines run the platform's default
  (ADR 0023).
- Accepted: Claude Code older than 2.1.281 skips the whole settings file,
  hooks included. A cloud routine's guard probe would not be refused, so the
  run stops. An interactive session on such a machine would run unguarded.
  The machines in use run 2.1.299 and later.
- Accepted, until a follow-up change: the installer's merge lets a later
  layer's value win over a scalar, so an instance or machine layer that sets
  `attribution` would replace `false` without a warning. No layer sets it
  today. The follow-up makes the merge refuse such a layer.

## Trial, still open

After a pin moves to a base carrying this change: one routine run that opens
a PR. Its body is checked for the footer before verify-body runs; the run's
log says whether verify-body took one off. Record the result here; if the
footer persists, report it upstream.
