# 0025. Installed settings turn commit and PR attribution off

## Status

Accepted (2026-10-14), by the operator. Whether it stops the PR footer awaits
a trial; see "Trial, still open" below. Supersedes the setting part of ADR
0022.

2026-10-15: it does not stop the footer; see "First trial" below. The
decision stands for the commit and Claude Code's own lines.

2026-10-16: a second trial, on two more runs, found the same; see "Second
trial" below.

## Context

ADR 0022's trial (2026-10-14) ran a cloud routine on a base that installs
`"attribution": {"sessionUrl": false}`. The commit carried no session
trailer, but the PR body still ended with a `---` /
`_Generated by [Claude Code](<session link>)_` footer. `sessionUrl: false`
does not reach it, and no documented setting names it. ADR 0024
(verify-body) now reads back each body a run creates and takes that footer
off after publication; it does not depend on this change.

What remains of the default attribution is Claude Code's own trailer and PR
line. The routine prompts and commands write both lines themselves (ADR
0022's rule), so the default adds nothing a run needs.

## Decision

`settings.base.json` sets
`"attribution": {"commit": "", "pr": "", "sessionUrl": false}`: no default
commit attribution, no default PR attribution, no session link. A bootstrap
test reads the value back from the installed settings and compares it as
JSON, exactly. The installer refuses an instance or machine layer that sets
`attribution` (ADR 0026), so the base's value is the installed one.

## Options considered

- **`"attribution": false`.** The settings reference says it hides all
  attribution, and it was chosen first (2026-10-14), to try whether it also
  stops the footer. Rejected: Claude Code older than 2.1.281 skips the whole
  settings file when it holds this value, hooks included, so every guard
  would be off with no signal; and nothing says it reaches the footer.
- **`false` with an installer version check (tried, then reverted).** The
  installer refused a `claude` on PATH older than 2.1.281, or one that
  reported no version, with five bootstrap tests. Reverted before merge:
  install time cannot close the gap. It checks only the first `claude` on the
  installer's PATH, not the copy an IDE extension or the desktop app runs; it
  has to pass when no `claude` is on PATH (CI, a machine before Claude Code is
  installed); it does not see a downgrade after the install; and the
  SessionStart hook that would warn of missing guards is registered in the
  file an old version skips.
- **The wanted lines as `commit` and `pr`, with `sessionUrl: false`**
  (`"commit": "Co-Authored-By: Claude <noreply@anthropic.com>"`,
  `"pr": "🤖 Generated with [Claude Code](https://claude.com/claude-code)"`).
  Interactive sessions would keep their attribution, and the text would live
  in one place instead of in every copy of the rule. Rejected: it is close to
  the configuration ADR 0022's trial already ran (attribution text on, session
  link off), which still got the footer, so it cannot tell whether turning PR
  attribution off stops it. Only empty strings answer that. Expectations are
  low: ADR 0022 records that empty `commit` or `pr` strings do not remove the
  session link from Claude Code's own lines, and the footer, which no setting
  is documented to reach, may come from the platform instead (see
  Consequences).
- **`sessionUrl: false` alone (ADR 0022).** Rejected: sessions keep adding the
  default trailer and PR line, which the prompts already write, and the
  trial showed it does not stop the footer.
- **Keep `sessionUrl: false` and rely on verify-body (ADR 0024) alone.**
  Rejected: verify-body takes the footer off only after the PR is published.
  For the settle time the footer is live, and a notification or webhook sent
  then carries it; GitHub's edit history keeps it for anyone who can read the
  repository. If this setting stops it at the source, both are avoided;
  verify-body stays as the read-back either way.
- **Server-managed settings.** Not taken: an organisation setting outside the
  base and the instance, invisible to their review.

## Consequences

- Every session on a machine running this base stops adding the
  `Co-Authored-By:` trailer and the `🤖 Generated with` line. ADR 0022's rule
  in the routine prompts and commands gives both lines in full
  (`Co-Authored-By: Claude <noreply@anthropic.com>` and
  `🤖 Generated with [Claude Code](https://claude.com/claude-code)`), since it
  can no longer rely on the default to supply them; the drift and render
  tests pin every copy. The trailer names no model: the routines run the
  platform's default (ADR 0023).
- An interactive session's commits and PRs carry no attribution unless the
  instance's own instructions add it.
- Every Claude Code version that reads `attribution` reads this form; no
  version floor is needed.
- Accepted: if the footer comes from the platform rather than from these
  settings, this change does not stop it, and verify-body remains the only
  thing that takes it off.

## Trial, still open

Closed 2026-10-16, except the upstream report: see "First trial" and "Second
trial" below.

After a pin moves to a base carrying this change: one routine run that opens
a PR. Its body is checked for the footer before verify-body runs; the run's
log says whether verify-body took one off. Record the result here; if the
footer persists, report it upstream.

## First trial (2026-10-15)

One manual run of a per-project conformance routine. Its installed settings
held `"attribution": {"commit": "", "pr": "", "sessionUrl": false}`, read
back by a run on the same base and environment the day before, which stopped
before writing.

- The commit ended at the `Co-Authored-By:` line the run wrote: no
  `Claude-Session:` trailer, nothing added.
- The PR body as created held the body sent, then a `---` rule and the
  session footer. When the run wrote the body back, the platform added a
  footer linking no session instead (ADR 0024, "First trial").

Result: the setting holds for the commit; it does not reach the PR footer,
which the platform adds on create and again on each edit. The consequence
accepted above holds: verify-body is what takes the session link off. The
footer persisting is for the operator to report upstream.

## Second trial (2026-10-15 and 2026-10-16)

A retro run (2026-10-15) and a conformance run (2026-10-16) of per-project
routines, with the same settings, on the base carrying ADR 0024's amended
read-back.

- Each commit ended at the `Co-Authored-By:` line the run wrote: no
  `Claude-Session:` trailer, nothing added.
- Each PR, created with `gh api` from the session, held the session footer
  after the body sent, as in the first trial; the write-back that took it
  off is recorded in ADR 0024, "Second trial".
- The retro's issue, created by `propose --apply`, held only the generic
  footer from its creation: no session footer.

Result: the same as the first trial. The setting holds for the commit and
does not reach the PR footer; verify-body takes the session link off. That
the issue was created with only the generic footer is recorded, not
explained: it may follow from how `propose` creates it, or from the issue
endpoint. The operator reported the footer upstream after ADR 0022's trial;
a further report, with this evidence that no attribution setting reaches it,
is the operator's.
